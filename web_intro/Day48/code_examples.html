Code Examples: Local Storage vs JSON Server

Side-by-Side Implementation Comparison

📝 Basic Operations

Adding Employee Data

💾 Local Storage
// Create employee object const employee = { name: "John Doe", department: "IT", salary: 50000, designation: "Developer" }; // Convert to JSON string const jsonString = JSON.stringify(employee); // Save to Local Storage localStorage.setItem('emp_1', jsonString); // Result: Data stored in browser's // Local Storage (isolated to this browser) localStorage.setItem('timestamp', new Date().toISOString()); // Verify it was saved console.log(localStorage.getItem('emp_1'));
🌐 JSON Server (HTTP)
// Create employee object const employee = { name: "John Doe", department: "IT", salary: 50000, designation: "Developer" }; // Send to server via HTTP POST fetch('http://localhost:3000/employees', { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify(employee) }) .then(response => response.json()) .then(data => { console.log('Added with ID:', data.id); // Result: Data stored on server // in db.json (accessible to all clients) }) .catch(error => console.error(error));

Retrieving Employee Data

💾 Local Storage
// Get single employee const empData = localStorage.getItem('emp_1'); const employee = JSON.parse(empData); console.log(employee.name); // "John Doe" // Get all employees (manual iteration) const allEmployees = []; for (let i = 0; i < localStorage.length; i++) { const key = localStorage.key(i); const value = localStorage.getItem(key); allEmployees.push(JSON.parse(value)); } console.log(allEmployees); // This data is ONLY in THIS browser // Other browsers won't have it
🌐 JSON Server (HTTP)
// Get single employee fetch('http://localhost:3000/employees/1') .then(response => response.json()) .then(employee => { console.log(employee.name); // "John Doe" }); // Get all employees fetch('http://localhost:3000/employees') .then(response => response.json()) .then(employees => { console.log(employees); }); // This data is SHARED on the server // ANY browser, ANY program can access it // Try in Postman: // GET http://localhost:3000/employees

Deleting Employee Data

💾 Local Storage
// Delete single employee localStorage.removeItem('emp_1'); // Delete all employees localStorage.clear(); // Verify deletion if (!localStorage.getItem('emp_1')) { console.log('Employee deleted'); } // Note: This only affects THIS browser // Other browsers still have their data // User A on Chrome: emp_1 deleted // User B on Firefox: emp_1 still exists // (if they had it in their storage)
🌐 JSON Server (HTTP)
// Delete single employee fetch('http://localhost:3000/employees/1', { method: 'DELETE' }) .then(response => response.json()) .then(data => { console.log('Employee deleted'); }); // Verify deletion fetch('http://localhost:3000/employees/1') .then(response => { if (response.status === 404) { console.log('Employee not found'); } }); // Note: This deletes from server // ALL browsers will see the deletion // Employee removed for everyone! // User A on Chrome: emp_1 deleted // User B on Firefox: emp_1 also deleted // (everyone sees updated db.json)

⚖️ Advantages and Disadvantages

Local Storage

✓ Advantages

  • No server required
  • Simple to implement
  • Fast access (local disk)
  • Works offline
  • No network latency
  • Persistent across sessions
  • GDPR friendly (local)

✗ Disadvantages

  • Browser-specific (isolated)
  • User-account specific
  • Device-bound data
  • No multi-user support
  • No data sharing
  • 5-10 MB capacity limit
  • Cannot sync across devices
  • Cleared on app uninstall

JSON Server

✓ Advantages

  • Centralized data storage
  • Accessible from any browser
  • True multi-user support
  • Real-time data sharing
  • No storage capacity limit
  • Works across devices
  • Works across networks
  • Any HTTP client can access

✗ Disadvantages

  • Requires server setup
  • Network dependency
  • Increased latency
  • Cannot work offline
  • Server maintenance needed
  • JSON Server is dev-only
  • No built-in authentication
  • Requires HTTP knowledge

🎯 Real-World Scenarios

Scenario 1: Team Collaboration

Requirement: 5 team members need to access the same employee payroll data from different computers/devices

❌ Local Storage Solution:

Each team member sees different data (trapped in their browser). Alice adds 10 employees, but Bob sees an empty list. No real-time updates. Collaboration is impossible.

✅ JSON Server Solution:

All 5 team members connect to the same server. When Alice adds an employee, everyone immediately sees it. Real-time updates for all. Perfect for team collaboration.

Scenario 2: Cross-Device Access

Requirement: User needs to access payroll data from office (Chrome), home (Firefox), and mobile (Safari)

❌ Local Storage Solution:

Data is isolated per browser. Chrome on office computer has different data than Firefox at home. Mobile phone has empty storage. No way to sync data across devices.

✅ JSON Server Solution:

All devices (Chrome, Firefox, Safari) connect to the same server. Data is always synchronized. User sees identical employee list from any device, anywhere.

Scenario 3: Different User Accounts

Requirement: Multiple Windows user accounts need access to payroll data

❌ Local Storage Solution:

Each Windows user account has completely separate Local Storage. User A adds employees, but User B cannot see them. Data is completely isolated per-user.

✅ JSON Server Solution:

Both Windows user accounts access the same server. User A and User B see identical employee data. User account is irrelevant - the server is the central authority.

Scenario 4: External Program Access

Requirement: Python script, Postman, cURL, and mobile app need to access payroll data

❌ Local Storage Solution:

Impossible! Local Storage is only accessible from JavaScript in a browser. External programs have zero access to the data. Not possible to implement.

✅ JSON Server Solution:

All clients (JavaScript, Python, Postman, cURL, mobile) use HTTP to access the same server. Any program with HTTP capability can access the data.

🔄 Request/Response Flow Comparison

Local Storage (No Network)

1
JavaScript runs in browser
2
Direct read/write to browser storage
3
Data stays in browser (isolated)
4
Other browsers have no access

JSON Server (Network Request)

1
Client sends HTTP request
2
Request travels over network
3
Server processes and reads db.json
4
Response sent to all clients simultaneously

🚀 Migration: From Local Storage to JSON Server

Step-by-Step Migration Example

Phase 1: Local Storage Implementation

// Original code - Local Storage only
function saveEmployee(emp) {
  const key = 'emp_' + emp.id;
  localStorage.setItem(key, JSON.stringify(emp));
}

function getEmployees() {
  const employees = [];
  for (let i = 0; i < localStorage.length; i++) {
    const key = localStorage.key(i);
    employees.push(JSON.parse(localStorage.getItem(key)));
  }
  return employees;
}

Phase 2: JSON Server Implementation

// New code - JSON Server
function saveEmployee(emp) {
  fetch('http://localhost:3000/employees', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(emp)
  })
  .then(r => r.json())
  .then(data => console.log('Saved:', data));
}

function getEmployees() {
  return fetch('http://localhost:3000/employees')
    .then(r => r.json());
}

The main differences:
• Storage changes from browser Local Storage to server db.json
• Access changes from synchronous to asynchronous (Promises)
• Scope changes from per-browser to global (all clients)

💡 Key Takeaway
Local Storage is a browser API for storing small amounts of data locally on the client machine. JSON Server implements a Client-Server architecture where the server is the central authority and all clients fetch data from it. This fundamental difference enables data sharing, multi-user access, and cross-browser/cross-device synchronization.
